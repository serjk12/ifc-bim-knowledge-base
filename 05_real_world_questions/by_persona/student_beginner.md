## In plain words

This persona is anyone new to IFC: a university student with an assignment or thesis, a junior architect or engineer who was just told "send the IFC", a Revit user moving to open-source tools, a developer arriving from outside construction, a teacher preparing a course. They are not stupid and not always young; the common factor is **they do not yet know what is in an IFC file or why the same file looks different in each program**.

They ask the questions that every other persona has forgotten to ask: *What is IFC? Is it a file or a standard? How is it different from RVT or DWG? Which IFC version do I choose? Why did all my columns become "proxy"? Where is the fire rating? What can open this file for free? Why is it blank?* They are the best test of whether an assistant explains in **plain words** and whether it dares to say "I looked in your file and here is what is there".

Most of the "I opened my file and nothing shows" messages in the data belong here, and so do the *"my prof says it should be X"* questions. They are also the persona most likely to be using an AI assistant instead of a forum: the data contains beginners asking whether Claude can open IFC directly or whether an MCP server is needed (`en-aimcp-s017`).

Evidence caveat: the research pass found English community material (OSArch, buildingSMART forum, GitHub) and several Japanese (Qiita), Chinese (Zhihu / SegmentFault / CSDN) and Spanish items. Real Russian, Portuguese, German, French, Korean and Italian beginner posts are few; many prompts in those languages below are synthetic.

## Goals

- **A learning path**: "where do I start?", a first project, a free viewer, plain explanations (`p-student-r001`, `p-student-r018`, `zh-revit-export-r025`, `ru-autodesk-telegram-r015`).
- **Pass the assignment or thesis**: counts, areas, material lists, storey trees from a given IFC (`p-student-s009`, `p-student-s011`, `p-student-s017`).
- **Know whose fault it is**: the file, the export settings, or the viewer (`en-osarch-r030`, `en-osarch-r031`, `p-student-r002`).
- **Send the right file to the right person** ("ifc vs rvt vs dwg - which one do I send to the contractor?", `en-beginner-qa-s006`; "can I just send the IFC to the teacher?", `p-student-s012`).
- **Teach or run a course** with software-neutral material and local-language textbooks (`en-osarch-r003`, `p-student-r003`, `p-student-r014`).

## Vocabulary they use (and what they do not know)

| They say | Meaning for them | What they usually do not know / confuse |
|---|---|---|
| "the IFC", "ифс", "IFC文件", "IFCファイル" | The file the architect sent | That IFC is both a *file format* and a *standard*; and that "an IFC" can be 2x3, 4 or 4.3 (`zh-zhihu-r001`). |
| "newbie", "absolute beginner", "complete freshies", "total newbie", "first time", "не шарю", "刚入门" | Self-label, politely apologetic | The vocabulary of the model itself (levels = building storeys; types vs instances). |
| IFC vs RVT vs DWG vs OBJ, "BIM", "openBIM", "BCF", "IDS", "COBie" | A soup of acronyms heard in class | That they are different things on different layers (format, process, checking rule, handover sheet): `ja-japan-r005` explains IFC like USB Type-C, BCF like GitHub Issues, IDS like a linter. |
| "viewer", "plugin", "converter", "Blender", "Bonsai", "Navisworks", "BIM Vision" | Tools they have heard of | What each tool can and cannot show (`en-beginner-qa-s003`). |
| "properties", "parameters", "attributes", "fire rating" | Data on an object | That properties live in named groups (property sets) and that missing ones mean the exporter did not write them (`it-italy-r012`). |
| "proxy" | A teacher's complaint | That the exporter chose the generic class because no mapping was set (`p-student-s010`). |
| "my professor / the client wants it in IFC" | Requirement from above | Which IFC version or "view" is meant (`en-mea-s011`, `en-uk-anz-india-s012`). |

Plain-language bridge: tell a non-BIM tester that an IFC file is like a **text inventory of a building**: a list of things (walls, doors, floors) and notes about them (type, material, fire rating, which floor they stand on). If the writer's program did not write a note, the note is simply not in the file. Background: [what IFC is and its versions](../../01_ifc_basics/01_what_is_ifc_and_versions.md), [IFC in real projects](../../01_ifc_basics/00_ifc_in_real_projects.md), [file anatomy](../../01_ifc_basics/02_ifc_file_anatomy.md), [entities cheat sheet](../../01_ifc_basics/03_entities_cheat_sheet.md), [sample IFC files](../../04_open_source/sample_ifc_files.md), [glossary](../../08_glossary/glossary_multilingual.md), [abbreviations](../../08_glossary/abbreviations.md).

## How to role-play this persona in tests

**Voice.** Friendly, a little apologetic, informal, often a non-native speaker of the language they type in. Self-labels: "newbie", "total newbie", "first time", "I'm an absolute beginner", "я новичок", "刚学". Starts with the situation, not the symptom: *"just got this ifc from my architect. what is even in it? like how many floors and what kind of stuff"* (`en-beginner-qa-s001`); *"i just opened my first ifc for uni, what even is in it?"* (`p-student-s001`); *"что такое IFC вообще"* (`ru-autodesk-telegram-r015`); *"IFC是什么，用什么软件可以打开IFC文件？"* (`p-student-r030`). Double question marks, "??", "pls", "lol" are fine. Greetings ("Hi all", "¡Hola!") and thanks appear in forum-style messages.

**Typical context.** A single IFC from an architect or a university course; a deadline (class, thesis, submission); no BIM licence on their laptop; an assignment sheet or professor's remark ("my prof says walls should be IfcWall"). They rarely give IFC version, software version, file size or the expected result. Often no file attached in the text; the MCP tester should make sure a file is loaded.

**Knowledge level.**
- Strong: whatever their field is (architecture, civil, CS); can follow a clear explanation and a simple table.
- Weak: nearly all IFC vocabulary; the file/standard/process distinction; why exports differ; what is optional in a file.
- Believes: "IFC is a 3D model format like OBJ"; "if my viewer shows nothing, the file is broken"; "the teacher/client wants IFC, there is one IFC".
- Will copy-paste an assistant's answer into an assignment, so wrong or invented numbers matter.

**What to test with this persona.**
- **Plain-language explanation** of what is in the file (counts by class, storey tree), without jargon dumps.
- **Honest limits**: "this file has no fire rating on any door" instead of an invented value; "I can see the file but not how Revit will display it".
- **Beginner traps**: the file is IFC2x3 vs IFC4 (they do not know), the file has proxies, the BaseQuantities are missing, the model is far from the origin (`en-viewconv-s017`).
- **Consistency of explanation across languages**: ru, zh, es, it, ja, ko, pt, de, fr, no.
- **Safe edits** requested by a beginner (`p-student-s006`): the assistant should explain the step, ask before writing, and work on a copy.
- **Recommendations** (free viewer, learning path) should be honest and not invent product claims: refer to tools in [viewers and checkers](../../03_software/viewers_checkers_cde_converters.md) and [community projects](../../04_open_source/community_projects_and_enthusiasts.md) instead of guessing.

**Typical follow-ups.**
1. "Wait, what is a property set?" / "а что такое пропертя" (expects a one-sentence plain definition)
2. "So should I send IFC or RVT?" (`en-beginner-qa-s006`)
3. "Is that normal? My teacher said it should not be proxy."
4. "Can you make a simple table I can paste in my report?"
5. "I don't have Revit, what do I install?" (`en-beginner-qa-s003`, `ru-autodesk-telegram-s014`)
6. "Can you explain that like I'm new to construction?"
7. "Is my file even valid?" (`en-beginner-qa-s011` family)

**Quick judge checklist.**
- Is the answer understandable without prior BIM knowledge, and does each new term get a one-line definition?
- Does it report what is actually in the file (numbers) rather than generic lecture text?
- Does it say so when something is absent, and avoid blaming the user's program without evidence?
- For recommendations: no invented features, prices or availability; points to documentation or says "I am not sure".
- Does it avoid overwhelming the user (one next step, not ten)?

## In plain words

A civil / infrastructure engineer designs things that are not buildings, or that surround buildings: roads, railways, bridges, tunnels, drainage and water/sewer networks (in Norway "VA", water and sewage), earthworks, terrain, utilities. Their world is built on **alignments** (the centre line of a road or track, defined by plan curves, a vertical profile and stations / chainage), **cross-sections**, **terrain surfaces** and **real-world coordinates** (national grids, EPSG codes). They work in Civil 3D, InfraWorks, OpenRoads, 12d, ProVI, Tekla (bridges), Revit (bridge components), QGIS and increasingly the open-source Bonsai / IfcOpenShell.

IFC matters to them because **IFC 4.3** (officially IFC4X3, with Add1 and Add2 releases) is the first version that really describes alignments, roads, rails, bridges and linear placement ("this signal is at station 12+500, 3 m to the left"). Before that, infrastructure was exported as a pile of generic proxy objects. In the data the persona is mainly the person who **receives a 4.3 file and finds nothing in it**, or who **cannot get the position right**.

A realistic caveat for test design: the real records for this persona are dominated by English GitHub and forum posts, and many of the people posting are developers or enthusiasts building tools (Bonsai alignment authoring, Saikei Civil). The practising road or rail designer appears less often; their voice is stronger in the Civil 3D forum items and the Norwegian / Italian / Chinese items. Russian real evidence is almost absent (2 records), so the Russian test prompts below that are marked "new synthetic" are extrapolations, not observations.

## Goals

- **See the alignment and the objects on it** after export, with the right stations (`en-civil-infra-r021`, `en-infra-r003`, `en-us-canada-infra-r036`).
- **A correct position**: no double application of map conversion, no millimetre / metre mix-up, no model at the origin or in the ocean (`en-bsforum-r025`, `en-gh-revit-ifc-r037`, `en-gh-thatopen-r052`).
- **Proper classes** (road, road part, pavement, kerb, bridge, bridge part, earthworks) instead of proxies (`en-civil-infra-r002`, `en-infra-r020`, `en-us-canada-infra-s003`).
- **A sensible hierarchy** for the facility: bridge vs road, which part holds the deck, kerbs, barriers; wearing course under bridge or road? (`en-us-canada-infra-r002`, `en-us-canada-infra-s013`).
- **Usable quantities** for earthworks and structures (`en-qto-r014`, `en-qto-s017`).
- **To know whether the receiving software supports IFC 4.3 at all**, and which version header it accepts (`en-autodesk-revit-import-r025`, `en-gh-thatopen-r020`, `it-italy-r016`).

## Vocabulary they use (and what they do not know)

| They say | Meaning for them | What they usually do not know / confuse |
|---|---|---|
| alignment, трасса, 线形 / 道路中线, Gradiente / Trassierung, 線形, 선형, asse | The centre line of a road or track | In IFC 4.3 it is a bundle: a horizontal part, a vertical part, optional cant, plus a 3D curve built from them; programs may export only one piece (`en-civil-infra-s001`). |
| station / chainage / пикетаж / Stationierung / PK | Distance along the alignment | The IFC attribute is "distance along" and may start from a start distance, which is not the same as a 0+000 label (`en-infra-s018`, `en-infra-r003`). |
| CRS, EPSG, EUREF89 NTM, MGA zone, CGCS2000, ETRS89 UTM, EPSG:27700, система координат | The coordinate system of the project | That IFC stores it in a map conversion + projected CRS pair and that one wrong unit factor moves everything (`en-gh-thatopen-r052`). |
| corridor, surface, TIN, terrain, DTM | Road model body / ground model | That the ground may be exported as a triangulated mesh object or not at all; that terrain voided by earthworks is not simple (`en-civil-infra-r030`). |
| superelevation, cant, clothoid / клотоида | Banking of the road / track and transition curve | That cant and superelevation may or may not be carried in the exported data. |
| VA, kummer, rør (no); culvert, manhole | Utility networks | The IFC 4.3 classes and the facility structure for them; the Norwegian group asks exactly this (`no-norway-r004`). |
| "IfcRoad", "IfcBridge", "IfcAlignment" (sometimes) | Class names they have seen in release notes | That these are *spatial / facility* containers, not the physical pavement or deck (`en-us-canada-infra-s001`). |
| "4.3", "4x3", "ADD2" | The version name | That header strings differ ("IFC4X3_ADD2" vs "IFC4X3") and some programs accept only one (`en-autodesk-revit-import-r025`). |

Plain-language bridge for a non-BIM tester: imagine a road as a long ribbon. The **alignment** is the ribbon's centre line on a map. **Stations** are the kilometre marks along it. Each object (a sign, a bridge pier, a kerb) can be placed by saying "at kilometre 12.5, 3 m to the left". IFC 4.3 stores both the ribbon and these "kilometre + offset" placements; older IFC could only store absolute x, y, z. Background: [IFC versions](../../01_ifc_basics/01_what_is_ifc_and_versions.md), [geometry, placement, coordinates, units](../../01_ifc_basics/06_geometry_placement_coordinates_units.md), [domains overview](../../01_ifc_basics/08_domains_mep_structural_infra_4d5d_fm.md), [Nordics](../../02_standards_regulations/national/nordics_baltics.md), [glossary](../../08_glossary/glossary_multilingual.md), sample files in [sample IFC files](../../04_open_source/sample_ifc_files.md).

## How to role-play this persona in tests

**Voice.** Plain-spoken surveyor / road designer who has read "IFC 4.3" in a press release. Practical and somewhat skeptical: they care whether the file works in the next program. Mixes professional shorthand (station, chainage, EPSG, MGA zone, EUREF89, "Gradiente", "пикетаж") with a little IFC vocabulary picked up from release notes ("IfcAlignment", "IfcRoad", "IfcBridge", "IfcLinearPlacement"). Questions are short and spatial: *"model opens far from origin in the viewer. what coordinate system is it using?"* (`en-mea-s006`), *"ligger veimodellen i riktig koordinatsystem?"* (`no-norway-s005`), *"这个ifc模型离原点特别远，看看有没有坐标系和EPSG"* (`mul-coord-s009`). Slightly irritated tone when something "lands in the ocean" or "nothing shows".

**Typical context.** A file from Civil 3D, InfraWorks, OpenRoads, ProVI, Tekla or Bonsai, version 4.3 (sometimes 4.1 or 2x3 for the surface), plus a GIS or Revit step that failed. They may know the EPSG code of their national grid (EPSG:27700, 25830, 3003, MGA 56, CGCS2000, NTM zone) and quote it. They rarely know which entity holds it.

**Knowledge level.**
- Strong: alignment design, stations, cross-sections, terrain, coordinate systems and map projections, national road / rail standards.
- Medium: file types and GIS tools.
- Weak: IFC entity names beyond a few headline ones, how a facility hierarchy is built (road vs road part vs bridge part), what a map conversion does mathematically, how linear placement works, which tool supports which 4.3 release.
- Misbelief to expect: "IFC 4.3 means everything will be interoperable"; "if it is in the file the viewer must show it".

**What to test with this persona.**
- Honest detection: the file is IFC4 with proxies only; or has an alignment without a vertical profile; or has a map conversion with the wrong unit. The assistant should say exactly what exists.
- Numbers with units and datum: eastings / northings, orthogonal height, rotation, scale factor, and the unit of the project.
- Version handling: the header says 4X3 ADD2, the tool expects another string.
- Language switching: Norwegian, Spanish, Italian, Chinese, Japanese, Korean, Portuguese, French, German prompts should return the same facts.
- Safe modification: "move model coords to origin, tell me the offset so I can put it back" (`en-gh-thatopen-s010`) requires the offset to be reported and the original untouched.

**Typical follow-ups.**
1. "Is that metres or millimetres?" (expects the unit assignment of the file, not a guess)
2. "And where is the model in the real world, put it on a map." (expects a lat/lon or an honest "cannot do without a CRS")
3. "Only the bridge, not the road." / "только мост"
4. "Give me start and end station for each alignment as a table."
5. "Compare to the previous version, what moved?" (`it-infra-s016`, `en-civil-infra-s010`)
6. "Will Revit / Civil 3D / QGIS open this?" (expects caution: depends on version and header)
7. "Export what you found as CSV." / "сохрани список в csv"

**Quick judge checklist.**
- Does the answer separate *spatial containers* (road, bridge, parts) from *physical elements* (pavement, deck, kerb)?
- Is any coordinate quoted together with its unit, CRS name and whether it is raw or converted?
- If the file is not 4.3, does the assistant say so instead of pretending to find alignments?
- Does it avoid claiming support of a specific commercial version it was not shown?
